Technical paper · PixelStow / PCF1

A diagonal-wavelet carrier for photographs that remain photographs

Andrew Cakebread · Massive Hadron · October 2026
Implementation reference: PictureCodec core (PCF1, carrier preamble C7) and the browser writer (carriers 3–5, default carrier 5). This paper describes the algorithms as implemented. It does not report a new optical trial.

Abstract

PixelStow embeds an arbitrary byte string in an ordinary RGBA picture by adding a known, mean-balanced diagonal wavelet to every complete 4×4 block. The same picture is a normal JPEG or PNG: a casual viewer sees the source, slightly softened by a reversible contrast reservation, and does not need to know that a payload is present. A reader that knows the carrier recovers the bytes from the pixels alone. A second, inverse step removes the wavelet and undoes the contrast reservation, restoring a source that is close to the original wherever the pixel lattice itself survived.

Reliability is bought with three separate mechanisms, and they must not be confused. Repetition, a soft correlator and a short parity code absorb small numeric errors such as JPEG quantisation on an unchanged pixel grid. Geometric markers and a low-amplitude edge calibration recover that grid after a photograph, a resize or a modest projective warp. A planning index — the photo-read prognosis — tells the writer how to spend resolution, repetition and wavelet amplitude before any camera is involved. The index is a designed margin, not a measured probability of a successful photograph.

The payload is opaque. Text, files and short voice recordings share one framed byte string. Voice is the retail path: a birthday card or a talking advert is a picture that plays audio when opened in a PixelStow viewer, and is still only a picture everywhere else. The inverse wavelet and the stored range map are sufficient for a future viewer plug-in to restore the source without interpreting the payload.

1. What the utility is trying to be

The design target is not a covert channel in the cryptographic sense, and it is not a separate container file. It is a picture that can be copied, posted and printed as a picture, and that still contains a checksummed byte string. Four properties follow from that target.

  • Native viewability. Before any decoder runs, the file is a JPEG or PNG. Most of the source contrast remains. The embedded signal is a structured, low-amplitude pattern, visible if one looks for it and easy to ignore if one does not.
  • Lattice survival. JPEG recompression that does not resample the image moves each sample by a small integer. The carrier is built so that a correlation against a known shape, summed over repeated copies, still has the correct sign.
  • Geometric survival. A phone photograph is a different lattice. Markers establish a homography back onto the original carrier pixels. A calibration band estimates scale before that search, so the expensive fit is not a blind scan of every magnification.
  • Opaque bytes, with audio as the default object. The carrier does not know whether it holds a greeting, a PDF, a game level or an Opus recording. Playback of audio is a front-end behaviour on top of that byte string, which is what makes “audio pictures” ordinary for a birthday card or an advert.

The C# core writes and reads the public PCF1 frame on carrier version 1. The browser adds carriers 3, 4 and 5, which keep the same payload frame and the same 4×4 wavelet, and add geometric markers so a photograph can be mapped back. Carrier 5 is the browser default. Desktop and older game readers still require carrier 1 until they are upgraded. Nothing in this paper changes the PCF1 byte layout.

2. Image model

Pixels are unpremultiplied 8-bit RGBA, rows top to bottom. Only complete 4×4 blocks are used. A picture of width W and height H therefore has

N = ⌊W/4⌋ · ⌊H/4⌋(1)

carrier cells. The incomplete right and bottom strips are never modified by the payload wavelet. Alpha is never modified. Encoding is limited to 24 megapixels in the browser writer and to 8,388,608 carrier blocks in the core settings; input photographs may be larger than the encoded carrier, up to a 32-megapixel read.

Colour samples are treated as integers in {0,…,255}. The luma used by the correlator is the sum of the three channels, not a television weighted luma. That choice is deliberate: the same integer kernel is added to R, G and B, so the decision statistic is exactly the inner product of the written pattern with itself, and a later JPEG step that treats the channels differently still leaves a large common-mode component.

3. The diagonal wavelet

3.1 Kernel

One bit occupies one 4×4 block. The shape is a seven-tap diagonal stencil

w = (−19, −11, 5, 13, 5, −11, −19),(2)

indexed so that the centre weight 13 sits at offset 0. For a pixel at local coordinates (x, y) ∈ {0,1,2,3}² the signed distance is

d1 = x − y,    d0 = x + y − 3,(3)

and the ideal integer step at amplitude a ∈ {1,…,32} is

δ(x,y; b, a) = round½(a · wdb+3 / 16),(4)

where round½ is the bias-free form (p+8)/16 for p≥0 and the matching negative form otherwise. Bit 1 therefore lies on the main diagonal and bit 0 on the anti-diagonal. The two patterns are not orthogonal in the strict inner-product sense, but they are opposite in sign along the diagonal that the reader measures, which is what the decision needs.

At amplitude 8 the centre weight is round(8·13/16) = 7 code values. At amplitude 20 it is 16. These are large compared with a fine JPEG quantiser and small compared with the 255-wide channel. That is the whole visibility bargain: the pattern is a few levels, repeated, and shaped so that a matched filter still sees it after the host texture and a quantiser have been added.

3.2 Staying inside the cube

An ideal step can push a channel outside [0,255]. For each channel the writer solves for a single bias s that brings every pixel of the block back inside the cube, choosing s = 0 whenever that is feasible. If no bias works, the legacy fallback reflects the step (δ becomes −δ) when that reflection fits, and writes nothing when neither orientation fits. A block whose simulated bit-1 score is not strictly positive, or whose bit-0 score is not strictly negative, is given a lower amplitude down to 1 and then abandoned. Abandoned blocks still occupy a grid slot; they are not a hidden mask. There is no external mask file and no template channel.

The simulated score is the same statistic the reader will compute. Let L1 and L0 be the 16 luma patterns of the two fitted bits, and let L be the pattern that would actually be written. The block is acceptable for amplitude a when

∑ L L1 − ∑ L L0   has the sign of the written bit.(5)

Writing therefore refuses amplitudes that the matched filter cannot separate on that particular texture. This is why a bright sky and a nearly black corner do not silently destroy a copy: the amplitude drops, or the block is skipped, rather than painting a clipped shape whose correlation has flipped.

3.3 Reading one block

The reader does not need the original picture. It correlates the observed luma with the two ideal shapes at a candidate amplitude and takes the sign. Repeated copies of the same coded bit are not decided one by one. Their scores are summed first — soft combining — and only then thresholded. A JPEG error that flips a minority of copies leaves the sum on the correct side of zero. The weakest absolute combined score is retained as a diagnostic of how close the frame came to a sign error; it is not itself the prognosis.

4. Framing, whitening, shuffle and parity

4.1 The preamble

The first 504 blocks are a fixed preamble: 9 bytes, 72 bits, each bit written seven times. Byte 0 is the magic 0xC7. Byte 1 is the carrier version. Byte 2 holds flags. Bytes 3–6 are the framed length as a little-endian 32-bit integer. Bytes 7–8 are the low 16 bits of CRC-32 over the first seven bytes. Seven repeats are enough to read the length and the flags even when a later payload code changes, which is why a newer carrier can be recognised and refused instead of being decoded as garbage.

On carrier 5, byte 2 still uses bit 1 to select one-parity mode. Bits 2–6 store the range headroom in steps of two code values. Two further bits select the calibration profile: no guide, the subtle edge guide, or a historical full-frame pilot. The preamble CRC covers those bits, so a reader does not guess which inverse to apply.

4.2 The payload frame

Inside the carrier sits a whitened PCF1 frame. Public text is envelope version 1, kind 1. Password-protected text is envelope 2. Attachments, including audio, are envelope 3 (public) or 4 (protected). The 20-byte header carries the ASCII magic, the envelope, the kind, a compression flag, the amplitude that was actually used, the uncompressed and stored lengths, and a CRC-32 of the header prefix plus the uncompressed body. The body is raw bytes or DEFLATE, whichever is smaller for public data. A decoder accepts the frame only after the checksum and, for text, a strict UTF-8 check.

Whitening is an xorshift byte stream with seed 0x50434631, the same seed that drives the Fisher–Yates shuffle of block order. Whitening stops the payload bytes from painting long runs of identical wavelets, which would be both more visible and more fragile to a local JPEG artefact. The shuffle spreads the copies of each coded bit across the picture so that one glare spot or one JPEG block does not remove every copy of the same bit.

Password protection does not change the wavelet. It wraps the body in a PSP1 envelope: PBKDF2-HMAC-SHA256 at 600,000 iterations, then AES-256-GCM. The GCM tag is checked before decompression. A locked image is detected from the envelope kind without the password, and a locked image is refused for re-encoding. No password is stored, and none is placed in a file name, a process argument or an export sidecar.

4.3 Repetition and the two parity modes

After the preamble, Np = N − 504 blocks remain. Each stored byte is expanded to either 12 or 9 coded symbols. Twelve symbols are an 8-bit value plus four Hamming parity checks. Nine symbols are the 8-bit value plus one parity bit, used when four checks would not leave even one full copy. If B is the framed length,

ρ = Np / (B · β),    β ∈ {12, 9},(6)

is the repetition ratio actually achieved, including the fraction of a copy. The integer copy count ⌊ρ⌋ is what soft combining sums. The fraction is what the amplitude policy and the prognosis use. Rounding ρ down to an integer before choosing amplitude would make a 1.9× payload look as fragile as a 1× payload, and would make the quality curve jump when the grid crosses a block boundary. The implementation therefore keeps the fraction until the final quantisation of amplitude to an integer.

Carrier 5 also refuses to place payload blocks under its markers. Four 52×52 corner reservations and four small side references remove 12,352 pixels, about 55% less reserved area than the eight large patches of carriers 3 and 4. Capacity is zero when those patches would not fit, or would exceed 30% of the picture. There is no silent fall-back from carrier 5 to carrier 1.

5. Prognosis, quality and resolution

This section is the planning layer. It runs before encoding, in the browser, and it never claims to be a camera success probability. The comments in the planner state that explicitly, and the shapes below are the reason the controls move the way they do.

5.1 Three quantities the user can actually trade

A fixed payload and a fixed source determine a capacity surface. The writer exposes three coordinates on it.

  • Resolution s, a scale of the source, snapped to a whole number of 4×4 blocks. More pixels mean more copies, and also a finer carrier pitch.
  • Repetition ρ, equation (6), on a common 12-symbol basis. A 9-symbol frame is scored as ρ·9/12 so that switching on Hamming parity does not look like a sudden loss of protection.
  • Quality q ∈ [0,1], default 0.8. This is not a JPEG quality factor. It is a gain on the wavelet amplitude,

g(q) = 20.8 − q.(7)

At q = 0.8 the gain is 1 and the accepted amplitude curve is used unchanged. At q = 1 the signal is about 13% gentler (2−0.2 ≈ 0.87). At q = 0 it is about 74% stronger (20.8 ≈ 1.74), before the hard ceilings. Quality does not change the payload bytes, the shuffle, or the number of copies. It only spends contrast.

5.2 Why resolution is not free

A larger carrier holds more copies, which helps. It also makes each carrier pixel a smaller fraction of a camera sensor, which hurts. The planner separates those effects instead of pretending that “more pixels” is monotone in reliability.

The reference lattice is 1200×800, chosen because that is the envelope in which camera reads of this carrier have been comfortable, not because it is an information-theoretic optimum. The resolution load of a candidate grid is

Λ = max(1, √(WH / (1200·800)) ).(8)

Below the reference, Λ = 1: shrinking further does not buy a sampling bonus in this model, because the failure mode of interest is undersampling a fine grid, not oversampling a coarse one. Above the reference, load grows with the geometric mean of the dimensions, so a 2× linear enlargement is load 2. Orientation does not matter. Λ is a planning weight. It is not a measured MTF of any lens.

The practical consequence is a bounded size gesture rather than “use the camera’s full 12 megapixels.” The planner searches scales whose repetition, on the same parity mode as the largest legal grid, lies between 1× and 3×. The search is a bisection on scale, 44 iterations, and each trial rounds width and height up to a multiple of 4 so that a one-pixel seam cannot change the parity mode. Crossing from the 9-symbol code to the 12-symbol code would otherwise drop the raw repeat count from about 1.33 to 1 at the same moment that error correction improved, and the slider would jump backwards. Holding the parity mode fixed during the gesture avoids that.

Moving the prognosis control to the left enlarges the carrier to buy repetition, up to 3× or until the 24-megapixel cap. Moving it to the right shrinks the carrier. The recommended default is 2×. A payload that cannot reach 1× inside the cap is reported as not fitting; carrier 5 will not quietly omit its markers to make room.

5.3 The protection curve against repetition

Let c = ρ · (9/12) when the short parity code is in use, and c = ρ otherwise. The planner turns c into a protection index π ∈ (0,1) by interpolating three anchors. The anchors themselves move with quality, because a stronger wavelet is a real change in margin, but they must move continuously: the writer’s amplitude is an integer, and a slider that jumped at each integer would feel broken and would not match the underlying fraction ρ.

The gain used in the anchor is not the full g(q) of equation (7). It is g(q) after the hard ceilings of the amplitude policy, estimated by

ĝ = 0.5 a/a0 + 0.35 t/t0 + 0.15 m/m0,(9)

where a, t and m are the policy’s nominal strength, texture gain and marker peak at the requested quality, and the subscript 0 is the same policy at q = 0.8. The weights say that nominal strength is most of the durability, texture boost is the next share, and the marker ceiling is a smaller share because markers are few and already have a high floor. Then each anchor is

A(c0, b, f) = clamp( b − 0.2 log2 ĝ(c0),   f,   0.98 ).(10)

The three anchors are A1 = A(1, 0.90, 0.75), A2 = A(2, 0.60, 0.50) and A5 = A(5, 0.20, 0.04). Their bases 0.90, 0.60 and 0.20 are judgements of remaining risk at one, two and five copies when the signal is at its nominal gain: one copy is still a poor photograph, two copies is the design point, and five copies is close to the floor of this index. The floors stop a quality boost from claiming that one copy has become safe. The coefficient 0.2 on the log gain is about one fifth of a stop of index per doubling of signal, which is intentionally modest: amplitude helps, but it does not replace a missing copy.

Between the anchors the index is piecewise linear in c, with a short ramp below one copy and a hyperbolic tail above five:

π(c) = A1 + (1−A1)·0.8·clamp((1−c)/0.25, 0, 1)   if c < 1,
A1 + (A2−A1)(c−1)   if 1 ≤ c < 2,
A2 + (A5−A2)(c−2)/3   if 2 ≤ c < 5,
0.04 + (A5−0.04)·5/c   if c ≥ 5. (11)

The factor 0.8 on the sub-unity ramp means that even a very short payload, which cannot reach one copy, does not immediately sit at “certain failure”; it sits near the one-copy anchor. The 1/c tail is diminishing returns: the tenth copy is worth less than the second, both visually (more amplitude is already available) and statistically (soft combining’s error rate falls quickly once the mean score is a few standard deviations from zero).

5.4 Folding in the resolution load

The number drawn on the prognosis bar is not π. It is the residual risk after the sampling penalty:

R = clamp( 1 − (1 − π) / Λ ,   0.04,   0.9999 ).(12)

If π is read as a notional failure tendency before sampling, then (1−π) is a notional success tendency, and dividing by Λ says that a grid twice as fine as the reference keeps only half of that tendency. The clamp at 0.04 matches the floor of the five-copy anchor: the bar never claims impossibility, and it never claims certainty. When the payload does not fit, the planner returns 0.99 so the bar sits at the dangerous end rather than at an undefined position.

Equation (12) is the reason a huge carrier with many copies can still look worse than a 2× carrier with fewer copies. The copies help π. The load Λ takes the help away again. Inside the 1×–3× window the repetition term wins as one moves left, which is why that window exists. Outside it, the model refuses to cooperate, because neither “tiny and fragile” nor “enormous and undersampled” is a setting the writer wants to recommend.

5.5 The quality ceiling at a chosen repetition

Once a grid is chosen, quality is not free to run to 1. The planner asks what gain would be required to hold the design point of 2× redundancy at quality 0.8, given the coverage actually achieved and the resolution load:

greq = √(2 / max(c, 0.01)) · Λ.(13)

The square root is the compromise between “repetition and amplitude are interchangeable on a linear scale,” which would be too kind to a 1× grid, and “amplitude cannot buy copies at all,” which would make the quality slider pointless. Solving (7) for the greatest q that still supplies greq gives

qmax = clamp( 0.8 − log2 greq ,   0,   1 ).(14)

The slider then lives in [0, qmax]. If the amplitude policy’s estimated gain (9) cannot reach greq even at full strength, the control is marked strength-limited: the ceilings have saturated, and asking for a prettier picture would drop the wavelet below the gain the planner used when it drew the bar. That warning is separate from the bar on purpose. Saturating the gain must not be drawn as if the optical problem had been solved.

Inverting the bar — the user drags the prognosis, and the writer picks either a scale or a quality — is a one-dimensional search, again 44 bisections, or a 101-step scan of quality when the grid is held fixed. Flat regions at the clamps are allowed. When several qualities hit the same risk, the one nearest 0.8 wins, so the control rests on the accepted curve instead of on an extreme that happens to score the same after a ceiling.

5.6 What this curve is not

There is no likelihood in equation (12). There is no training set. The anchors, the 0.2 coefficient, the square root in (13) and the 1200×800 reference are engineering judgements, written down so that the slider, the amplitude and the resize search agree with each other. A later optical campaign can replace Λ or the anchors without touching the wavelet, the frame or the checksum. Until that campaign exists, the honest statement is: the prognosis is a monotone planning coordinate for repetition, amplitude and carrier pitch. It is not a probability that a given phone, print or social network will decode.

6. How amplitude follows repetition

Carriers 4 and 5 do not use a single strength for every payload. Let r be the fractional repetition. Define the pressure toward the fragile end, and a smooth urgency that is zero at 2× and saturated at 1×:

p = clamp((5 − r)/4, 0, 1),    u = clamp(2 − r, 0, 1),    υ = u(2 − u).(15)

A reciprocal uplift raises the whole curve by 15% at r = 2 and relaxes as copies increase:

U(r) = 1 + 0.15 · (2 + 1) / (max(1, r) + 1).(16)

Nominal strength, before the quality gain (7), is

a0 = clamp( round( (8 + 12p + 12υ) U ) ,   8,   32 ),(17)

and at least the base discovery amplitude 8. At the 2× design point, p = 0.75, υ = 0 and U = 1.15, so the unrounded value is 19.55 and the stored amplitude is 20. At 5× and above, p = υ = 0 and the amplitude sits near 8, scaled only by the small remaining uplift. At 1.5× and below, urgency drives the value into the ceiling of 32. Spending contrast where copies are scarce, and withholding it where copies are plentiful, is the same idea as the prognosis anchors: the second copy is the precious one.

Texture is extra, and it is measured on the source, never on the bits about to be written. Over the 4×4 block (or the marker cell) the writer removes the mean and the best-fit brightness plane. The residual mean square is

σ2 = max(0,   ∑v2 − (∑v)2/n − (sx2 + sy2)/E ) / n,(18)

with n = 16 and E the usual centred-axis energy n(n−1)/12 for a unit grid. A smooth gradient has σ ≈ 0, so a sky does not get a boost merely for being brighter on one side. The working amplitude is min(peak, a0 + round(σ · t)), where the texture gain t is (0.175 + 0.825p)(1+υ)U and then multiplied by g(q). Payload peaks are capped at 64 and marker peaks at 32. A boost that would force a large per-channel bias, or a bias that differs by more than two levels across channels, is rejected and the nominal amplitude is kept. The boost is allowed to hide in texture. It is not allowed to repaint a flat colour or to clip a highlight.

Older carriers use a coarser table: four or more copies keep the base amplitude, three copies multiply by 1.5, two by 2, and one by 4, then clamp to 32. Carrier 5’s smooth curve is the one the prognosis assumes.

7. Range compression and the inverse that restores colour

A wavelet added to an already extreme colour either clips or shifts the whole block. Carrier 5 avoids both by reserving symmetric headroom before any wavelet is painted:

c′ = h + c · (255 − 2h) / 255,    h even,   0 ≤ h ≤ 62.(19)

Mid-grey, c = 127.5 in the real line, stays fixed. Black moves up to h and white moves down to 255−h. Alpha is untouched, and so is every pixel, including marker margins and the partial edge strips. The headroom is

h = min(62,   2 ⌈ (max(12, a) · 19/16 + blim + apilot) / 2 ⌉ ),(20)

that is, enough room for the raised centre lobe of the kernel, the permitted bias, and the calibration pilot if one is present, rounded up to the two-level step stored in the preamble. Because h is in the preamble and the preamble is checksummed, the inverse does not estimate black and white from the picture. After the wavelets have been subtracted it is exactly

c = (cclean − h) · 255 / (255 − 2h).(21)

This is the colour restoration. It is not a colour-matching algorithm and it does not invent texture that the wavelet overwrote. It puts the host back on the original 0…255 range so that a viewer plug-in can show a source whose contrast matches the input, rather than a picture that looks slightly washed out because headroom was left in.

The subtraction itself is a pair of projections, the same idea as the writer’s two shapes. From the fitted bit-0 and bit-1 luma kernels one builds the common-mode pattern κ = (L1+L0)/2, with its mean removed, and the difference pattern Δ = L1−L0. Observed luma y gives two scalars

μ = clamp( 〈y, κ〉 / ‖κ‖² , 0, 1 ),    β = clamp( 〈y, Δ〉 / ‖Δ‖² , −½, ½ ),(22)

and the reconstructed signal μ κ + β Δ is subtracted from each channel. The clamps stop a wild correlator, on a block the writer never touched, from carving a wavelet out of genuine texture. The wavelet view shown in the desktop tools is 128 + 4·signal, so zero signal is neutral grey.

Two losses remain, and both should be stated. Rounding to 8 bits at each step means (21) is not an integer inverse of (19) for every input value. JPEG quantisation, or any other small perturbation, means the subtracted pattern is the pattern the correlator believes, not necessarily the pattern that was added. On a native PNG round trip the residual is a level or two. On a photograph it is the residual of the resampling as well. The implementation does not call this a perfect inverse. It calls it a near restoration of range and of the host, which is the right claim for a viewer plug-in.

8. Markers and the projective model

8.1 What a marker is

A photograph does not present the 4×4 lattice. Carrier 5 therefore paints four square patches, each 50×50 pixels, inset from the corners. Each patch is a 10×10 array of symbols that are the same diagonal wavelet, resampled from four pixels to five by the symmetric map (i+½)·4/5 − ½, with the kernel mean removed and the outer row and column tapered by 0.7. The patch carries eight bytes: a magic, an identifier in {0, 2, 6, 8} for the four corners, the original width and height as little-endian 16-bit integers, and the low 16 bits of a CRC over the first six bytes. Whitening and scatter use a marker seed distinct from the payload seed. The first 24 coded bits are pilots. A marker is accepted only when the decoded header matches its CRC. A strong periodic score is not acceptance.

The identifiers fix orientation. The stored width and height fix the source rectangle that the homography must explain. Four centres in the plane, no three collinear, determine a homography; three centres do not, because a homography has eight degrees of freedom and each point in the plane supplies two.

Four smaller patches, 24×16, sit at the side midpoints. They repeat only a fragment of the magic and the identifier, at 0.65 of the main marker strength. They are checked after the homography exists. A hit records a displacement in carrier pixels. A miss does not fail the picture. They are there for a later lens model; they are not yet a lens model.

Marker amplitude has a floor of at least 12, and a texture-gain floor of 0.5, because a marker header has far fewer repeats than the payload. The same quality gain (7) scales them, and the same headroom (19) bounds them. They are visible if one crops in on a corner. They are not a QR code, and they are not required for a native, unresampled read: a generated image is verified on the integer grid with no search.

8.2 The homography

A carrier pixel (x, y) is sent to the photograph by a 3×3 matrix H, stored row-major and scaled so that H33 = 1:

u = (H11x + H12y + H13) / D,   v = (H21x + H22y + H23) / D,   D = H31x + H32y + 1.(23)

This is the standard projective map of the plane. It includes translation, rotation, scale, shear and the keystone of a page photographed at an angle. It does not include a fisheye. The inverse, used when sampling the photograph back onto the carrier lattice, is the adjugate of H divided by det H, rejected if the determinant is below 10−12.

Given pairs (xi, yi) ↔ (ui, vi), the fit is a weighted least-squares problem on a normalised copy of the points. Each cloud is translated to its centroid and scaled so that the root-mean-square distance from the centroid is √2, the Hartley normalisation that keeps the eight-by-eight normal matrix from mixing pixels with pixels-squared. The projective unknowns satisfy, for each pair,

x h1 + y h2 + h3 − u x h7 − u y h8 = u,
x h4 + y h5 + h6 − v x h7 − v y h8 = v,(24)

and the six-unknown affine case is the same system with h7 = h8 = 0. The normal equations are solved by Gaussian elimination with partial pivoting, abandoned if a pivot falls below 10−10. The normalisation is then undone by Ttarget−1 Hnorm Tsource. Four correspondences determine the projective map. Further marker-interior samples, taken at 0.65 of the way from a patch centre to its measured local axes, overdetermine it and let a bad fourth corner be dropped.

A candidate is refused if any three of the points are nearly collinear, measured by the area of the triangle against the longest side. The three top patches plus one side midpoint are the classic singular set, and the fitter knows that. It is also refused if any corner of the recovered rectangle falls more than a search margin outside the photograph: a homography that explains the markers by sending the payload off the sensor is not a read.

8.3 Sampling back onto the carrier

Once H is accepted, every output pixel is a carrier pixel, not a triangle in the photograph. For carrier site (x, y) the map (23) gives the centre in the capture. The local derivatives of (23) give the footprint of that one carrier pixel in capture pixels, and the sampler takes an nx×ny grid over that footprint, with 1 ≤ n ≤ 8, bilinear in the capture. The projective denominator is evaluated at each subsample, so the footprint is not a parallelogram frozen at the centre. The result is a picture whose 4×4 blocks sit on the original lattice, and the ordinary native decoder runs on it. No second copy of the payload format exists for the camera path.

9. Calibration, and why it makes the search fast

A blind search would try many scales, many positions and many small rotations, and at each one would hunt for the four markers. Carrier 5 paints a second, much quieter signal whose only job is to estimate scale and the rough quadrilateral before that hunt.

Along each edge, inset by 8 pixels and avoiding the marker reservations, a band 48 pixels deep carries

γ(t, n) = round( cos(2π t/64 + 0.31) + cos(2π t/96 + 1.19) ) · sin(π (n+½)/48) · cos(2π n/24 + 0.43),(25)

clipped to ±2 code values. The tangent t runs along the edge and the normal n runs across the band. The two pitches, 64 and 96, are incommensurate enough to identify a scale rather than a harmonic. The sine envelope rises and falls once across the band so that a hard edge in the host picture is not itself a detection. The normal cosine keeps the band from being a flat tint.

The colour pattern is the part that makes the guide nearly invisible and still measurable. The integer γ is added to red, subtracted from green, and added to blue. On a luminance the three steps cancel to first order: +γ −γ +γ leaves +γ only if one looks at red or blue against green. A casual glance, and a JPEG quantiser that spends its bits on luma, mostly sees nothing. A reader that forms a chroma difference sees a pair of known spatial frequencies.

Detection, on a reduced working image, is a set of sliding inner products against the complex tones e±i 2π x / (pitch · scale), implemented as prefix sums so each window is a subtraction. The 48-pixel envelope is itself detrended — mean and slope removed — before the correlation, for the same reason the texture boost ignores a brightness plane. A candidate scale is kept when the two pitches agree, the four edges form a quadrilateral of plausible area, and the phase residual is small. The reported scale is capture pixels per carrier pixel.

That single number changes the decoder. Marker search can be started at the predicted pitch instead of at a ladder of unrelated magnifications. The homography fitter can be seeded with the quadrilateral of the bands. Frames that do not contain the guide are not failed; they take the ordinary search. Frames that contain a false guide are not accepted either, because acceptance is still the marker CRC and then the payload CRC. The guide is a hint with a budget of a few seconds. It is not evidence.

In the live camera this is also a scheduling device. A cheap guide check on a downscaled copy decides whether a full-resolution frame is worth a marker worker. The preview shows only “searching”, “no signal” or “calibration found”. The scale number stays in the scan notes. None of that guide is required for a file that was never resampled.

10. Sub-pixel phase on the carrier lattice

A homography lands each carrier pixel on a point that is not an integer capture pixel. Residual error after the homography is often a slowly varying shift of a fraction of a carrier pixel, from lens distortion, from a page that is not perfectly flat, or from the bilinear kernel itself. The reader looks for that shift in the carrier’s own four-pixel periodicity.

Over a window, second differences of luma are correlated with a complex tone of period 4. The phase of that correlation is a local offset (ox, oy). Neighbouring windows unwrap the phase by adding or subtracting 4 when the jump exceeds half a period, so the field stays continuous. An offset larger than 8 pixels is rejected: the homography was wrong, and a phase tracker must not invent an eight-pixel slide. Windows are kept only when a large fraction of them, currently 70%, show a strong four-pixel peak.

The rectifying sampler adds this field, or a spline built from it, to the carrier coordinate before evaluating (23). Where the spline is used, each subsample also gets the local Jacobian, so the integration footprint follows the curved pixel instead of a rigid square. Sixteen spline controls are not revisited for every subsample; a quadratic expansion of the displacement is enough inside one carrier pixel. This is what “fast transform decoding” means in the implementation: the calibration picks the scale, four markers fix H, and a single resampled lattice is handed to the same wavelet decoder that reads a PNG.

11. JPEG, social platforms, and what “immune” can mean

A JPEG file of this carrier is already a normal photograph. The useful claim is narrower than “any repost survives,” and wider than “only PNG works.”

11.1 Same lattice, new quantiser

Baseline JPEG transforms non-overlapping 8×8 blocks. The carrier’s energy lives on a 4×4 diagonal, so inside each 8×8 block it occupies a small set of DCT coefficients, mostly at mid frequencies rather than in the DC term. A quantiser replaces each coefficient F by a multiple of a step Q. The error in the pixel domain is bounded by the synthesis of those steps. Two properties of the writer meet that error.

  • The matched filter (5) is a sum of sixteen pixels against a shape whose centre lobe is many quantiser steps wide once a is in the tens. A small Q moves the score. It rarely flips the sign of a single clean copy, and it more rarely flips the sign of the soft sum over ρ copies.
  • The copies are shuffled. A quantiser artefact is local to an 8×8 block. The copies of one payload bit are not local to one block. Soft combining is then an average over independent quantiser errors, which is the classical reason repetition coding survives a memoryless channel.

The parity bits sit inside that average. They are not a substitute for repetition. They correct the rare bit whose combined score was on the wrong side after the quantiser, provided the surrounding bytes were right. This is why the planner treats the 12-symbol code as more protection rather than as fewer copies, and why equation (6) rescales the 9-symbol code before drawing the bar.

Headroom (19) matters here as well. A wavelet that was already clipped has a distorted shape, and the inner product with the ideal shape shrinks. Reserving range before painting means the shape that JPEG quantises is the shape the reader knows.

So the designed immunity is: re-encode as JPEG at the same width and height, at a quality that does not wipe mid-frequency coefficients below the correlator’s margin. That is exactly the operation a messaging application performs when it recompresses a photo without resizing it. It is why a picture can move through such a channel as a picture.

11.2 A new lattice is a different problem

The moment a platform scales, crops, or heavily recompresses after a resize, the 4×4 phase is gone and section 11.1 no longer applies. Nothing in the wavelet is immune to that. The markers and the calibration of sections 8 and 9 are the answer, and they are a search, not a guarantee. The project’s own measurements say the same thing: a native round trip, including a JPEG that keeps the grid, is a different result from a social down-sample or a photograph of a screen. The prognosis exists so that a sender who expects a resize can buy copies and a coarser pitch before the picture leaves, instead of discovering the loss afterwards. Buying those copies does not extend a promise to every network’s image pipeline.

11.3 Why the untouched JPEG is already distributable

Before any of that damage, the encoded file does not need a special extension or a special viewer to be posted. It is a JPEG. The host image occupies the same pixels. The contrast change is the global map (19), a few levels at each end of the histogram, which readers experience as a slightly softer master rather than as a damaged one. The wavelet is a diagonal shimmer at the amplitude chosen in section 6, strongest where the picture is already busy, withheld on flat regions that cannot hide it, and withheld entirely where it would clip. The markers are four small corner patches and four slivers on the sides. A person who is not looking for a carrier sees a photograph. A person who is looking can find the corners. That asymmetry is the portability.

12. Any byte string, and audio as the ordinary object

The carrier’s contract is a length-prefixed, checksummed byte string. PCF1 kind 1 is UTF-8 text, limited to 16 KiB. Kind 3 is a bundle: optional text plus between one and eight files, the uncompressed bundle limited to 1 MiB, each file opaque. Filenames and media types travel inside the bundle. A game level can be one JSON file and one zip file. A PDF can be one file. A voice note is one audio file. The wavelet, the repetition and the prognosis do not branch on the media type. Capacity is a function of Np, β and the framed length, nothing else.

Voice is special only in the front end, and that is a product decision rather than a codec one. A short recording is encoded as Opus in a WebM or M4A container, at a low bitrate so that a greeting fits a modest picture, and stored as one attachment. On decode, the viewer sees that the attachment is audio and plays it. The picture is the card; the sound is what the card was for. The same mechanism is a talking advert: the poster is the JPEG, the speech is the payload, and a platform that only displays the JPEG has still displayed the advert. A platform, or a future plug-in, that understands the carrier also plays it.

Protected bundles are compressed, then sealed with the same AES-GCM envelope as protected text. The password never becomes part of the image metadata. Re-locking discards the decoded bytes. A locked image cannot be used as a source for a new encode, because the writer refuses any picture whose preamble and frame already check out.

13. A viewer plug-in, and restoration without curiosity

Everything required to show a cleaner source is in the pixels. A plug-in does not need to parse the payload, and it does not need a network.

  1. Read the 4×4 grid far enough to combine the preamble copies. Check the magic, the version and the CRC. Refuse a version the plug-in does not know.
  2. Read the flags: parity mode, headroom h, calibration profile, and the framed length.
  3. If the grid is not the native lattice, this plug-in may stop and show the JPEG as it stands. A full plug-in runs the marker fit and the resample of sections 8–10, then continues on the rectified lattice.
  4. Soft-combine and parity-decode the frame far enough to know the amplitude that was stored in the PCF1 header. That amplitude, not a guessed one, selects the kernels κ and Δ.
  5. Subtract (22). If the calibration profile says an edge guide or a pilot is present, subtract that integer field too. It was added with the opposite sign on green, so the inverse is the same formula with the sign flipped, and it is an exact integer inverse when no quantiser has touched it.
  6. Apply (21) with the h from the preamble.

Steps 4–6 are the “near perfect” restoration on a file whose lattice survived. They are deterministic. They do not need the message, the files or the password. A locked picture restores its host exactly as a public picture does; the password only opens the body. The residual is quantisation and rounding, which on a native file is at the level of the 8-bit grid, and on a requantised JPEG is at the level of the surviving correlator. The plug-in can offer “show original” as a view, while the file on disk remains the ordinary JPEG that everyone else is already passing around.

The same plug-in is the retail player. If it does continue into the payload and finds an audio attachment, it plays it. If it finds text, it shows it. If it finds nothing it understands, the restored picture was still worth the click. That is the sense in which simple viewing and audio pictures are the same mechanism: one carrier, one inverse, and a front end that prefers to play sound when sound is what the bytes contain.

14. Other mechanisms that earn their keep

No mask. Early experiments excluded a rectangle with an external mask. The current writer does not. Every complete block is in the grid, markers punch explicit holes that the reader can recompute from the width and height, and a legacy import may only infer an old exclusion from the signal itself. A file never depends on a sidecar to be readable.

Strength is stored, then rediscovered. The header records the amplitude that was written. Readers still try the ladder 8, 12, 16, 24, 32 when the header is not yet known, and they keep a candidate only when the frame checksum matches. A photograph that was decoded at the wrong amplitude does not return plausible text.

Adaptive amplitude is local and reversible in intent. Texture gain is computed from the source before painting. The inverse uses the amplitude the header names, not a second measurement of the encoded texture, so the reader and the writer agree on the kernel even where the boost differed from block to block. Where the boost was rejected by the bias limit, the nominal kernel is what was written, and it is what is removed.

The guide is chroma-neutral on purpose. Equation (25) plus the opposing green step is a small example of the same idea as the whole carrier: put the information in a subspace people and JPEG quantisers under-use, and put a matched filter in the decoder that looks only there. The payload uses a diagonal subspace of luma. The guide uses a pair of spatial frequencies in a red-minus-green direction. They do not share a detection statistic, so a strong guide cannot impersonate a payload, and a strong payload cannot impersonate a guide.

Scheduling on the camera is part of the algorithm. A live preview produces more frames than a decoder can finish. The implementation keeps a short history of marker-bearing frames, prefers a frame whose calibration scale agreed, and will not spend a payload read on a frame with no marker candidate. A homography that fails its checksum yields to a newer frame. The calibration budget is intentionally cheaper than the marker budget. This is not a mathematical curiosity; it is why a phone can show a live picture and still decode, instead of freezing on the first blurry grab.

Comparison without a second encode. After a read, the source view is the inverse of section 7 applied to the pixels just decoded. It is not a stored original. That is what lets a viewer show “before and after” for a file that arrived with no companion, and what a plug-in can do in place.

15. Limits that the mathematics does not remove

These are part of the design, not a list of future work disguised as modesty.

  • The prognosis is not a probability. Replacing equation (12) with a fitted model would be a new measurement, not a bug fix.
  • A homography is not a lens. Curved paper, strong fisheye and heavy motion blur are outside sections 8–10. Side-reference displacements are recorded and not yet consumed by a distortion model.
  • The inverse (21)–(22) cannot recreate texture that was never captured, or that a platform removed by scaling. “Near perfect” applies to the host on a surviving lattice.
  • Carrier 1 and carrier 5 are different marker layouts. A reader must honour the version byte. There is no single image that is native to every historical reader.
  • Capacity is real. A long recording or a large file that cannot reach one copy at the encoding cap is refused. Repetition cannot be conjured from a grid that does not have the blocks.
  • The embedded pattern is a signal, not a secret. Anyone who knows this paper can detect and remove it. The goal is portability and restoration, not concealment from a determined analyst.

17. Conclusion

PixelStow is a carrier that respects the fact that its cover is the product. The mathematics that makes the bytes reliable — a known diagonal shape, a cube-safe integer amplitude, a shuffled repetition code, a soft sum, a short parity check, a checksummed frame — is the same mathematics that makes a mild JPEG survivable, because a mild JPEG is a small error on that shape. The mathematics that makes a photograph readable — four identified corners, a normalised homography, a chroma-opposed scale guide, a four-pixel phase field — is separate, and it is what puts the bytes back on the lattice the first mathematics understands. The prognosis is the negotiated truce between those two: more copies help the code, a finer pitch hurts the camera, and amplitude can only pay for part of the difference.

The inverse is short enough to live in a viewer. Subtract the wavelet the header names, subtract the guide the preamble names, and expand the headroom the preamble names. The picture that comes back is the host. The bytes that come with it may be a sentence, a file, or a voice. For a birthday card or a talking advert, the voice is the point, and the fact that everyone else can still pass the JPEG around, oblivious, is the distribution system.
