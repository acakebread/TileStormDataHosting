About PixelStow

PixelStow puts a message, files or a short voice recording inside a photo. The encoded image carries those contents, so someone with the image can open it in PixelStow.

Getting started

  1. Choose a source photo. Browse for an image, paste one, or take a source photo with the camera.
  2. Add your contents. Enter a message, attach files or record audio. Leave the password blank for public contents, or set a password to lock them.
  3. Encode and save. Encoding creates a new image. Keep the downloaded encoded PNG; your original source file is preserved.

To open an encoded image, use Browse or Paste in PixelStow. If it is locked, enter its password. Recovered messages, audio and files appear under Image contents.

For a resized or photographed image that Browse does not recognise, try Image recovery options. Holding the preview also starts a full search when no decoded image is available. Camera reading can work with images displayed on a screen or printed, but recovery depends on framing, focus, lighting and image quality.

If a decoded message starts with a web link, PixelStow asks whether to open it. Choose Not now to keep reading; the Open link button remains available.

Sharing encoded images

Send the original encoded PNG as a file or document. Messaging and social apps can resize or recompress photos, which may damage the embedded contents. Include the PixelStow opening link so the recipient knows where to read the image.

A JPEG download is offered only when PixelStow has checked that the exported JPEG still contains the message and every attachment. That check applies to the saved file; further editing or compression can still affect recovery.

Larger messages and attachments need more image capacity. The suggested size and read margin help you choose a suitable image. Smaller source images normally keep their native resolution to preserve their appearance.

Passwords and privacy

Encoding and decoding happen locally in your browser. PixelStow does not upload your source image, message, attachments or password.

A blank password leaves the contents public. A password encrypts the message and attachments, including their filenames. The photo itself remains visible. The password is not stored in the image, so keep it separately.

Encoding formats

Use Version 6 for new images. It is the default and the format used by normal Browse and camera recovery. The older writer choices remain available for compatibility work and comparison.

Formats available in the Encoding format selector
FormatPurpose
Version 6The current format, with compact recovery markers, adaptive signal strength and a reversible brightness curve. An optional reference records the original tones and colours for image restoration.
Version 5An earlier format with compact recovery markers and adaptive contrast. Retained for comparison with earlier exports.
Version 4An older format using larger recovery patches and marker brightness balancing.
Version 3An earlier recovery format with larger markers around the image.
Version 1The original image carrier. Retained for compatibility with readers that use the original format.

Normal image and camera searches read Version 6 only. Selecting an older writer checks the image it generates using that format, but does not enable automatic recovery of older images. Use a format supported by the recipient's reader when compatibility is required.
